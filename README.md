# Storager

macOS 메뉴바에 상주하는 디스크 용량 분석 앱. 홈 폴더를 스캔해 무엇이 공간을 차지하는지 분류·시각화하고(개발자 빌드 캐시, 패키지 관리자 캐시, AI 도구 데이터 등), 다시 만들어지는 캐시를 휴지통으로 정리하며, 카테고리별 용량 추세를 보여 줍니다. "시스템 데이터랑 빌드 캐시가 디스크를 다 먹는다" 에 대한 답으로 만들었습니다.

릴리스는 [GitHub Releases](https://github.com/WoojinByun/Storager/releases) 페이지에서 받을 수 있습니다.

## 주요 기능

- 메뉴바 표시 템플릿: `{icon}{remain_storage}` 처럼 토큰과 글자를 섞어 씁니다. 크기 100~200%, 템플릿 이미지(단색) 켬/끔
- 팝오버: 볼륨 막대(사용 / 퍼지 가능 / 여유), 카테고리 카드(크기, 도구별 내역, 7일 변화량), 재생성 가능 항목 "정리" 버튼
- 분석 윈도우: 홈 트리맵(경로 해시 색), 카테고리(도구 필터), 큰 파일, 트리 보기
- 안전한 정리: "재생성 가능" 등급 + 휴지통 이동 항목만, 미리보기 후 실행, 실행 직전 다시 확인, Xcode 등 관련 앱이 실행 중이면 경고, 상태가 바뀌면 "다시 계획"
- 스냅샷 저장과 7일 변화량 표시
- 주기 스캔 (기본 6시간, 배터리 전원·저전력 모드에서는 건너뜀)
- 전체 디스크 접근 권한 안내 (권한 없이도 보호 폴더만 건너뛰고 스캔)
- 홈 밖 추가 프로젝트 루트, 제외 경로, 무시 목록
- 로그인 시 실행 옵션 (기본 꺼짐)

분류하는 카테고리: Xcode, 시뮬레이터, Gradle, JavaScript(pnpm·npm·yarn·bun 등), CocoaPods·SwiftPM, Docker, Homebrew, AI 도구(Claude·Codex·Cursor), Python(pip·uv·conda·poetry·pyenv·pipx 등), Rust, Go, 캐시, 로그, 메일·메시지·사진.

## 요구 사항

- macOS 15 이상
- Apple Silicon (arm64) 전용입니다. Intel Mac 은 지원하지 않습니다.

## 설치 (사용자용)

1. [GitHub Releases 최신 버전](https://github.com/WoojinByun/Storager/releases/latest)에서 `Storager-x.y.z.zip` 을 내려받습니다.
2. 압축을 풀고 `Storager.app` 을 `/Applications` 로 옮깁니다.

### Gatekeeper

앱이 notarize 되어 있지 않고 자체 서명 인증서로만 서명되어 있어 첫 실행이 차단됩니다. macOS 15 이상에서는 우클릭 → 열기로 우회할 수 없습니다. 아래 둘 중 하나를 사용하세요. (한 번만 하면 됩니다.)

1. 시스템 설정 → 개인정보 보호 및 보안 → 아래로 스크롤 → "그래도 열기"
2. 터미널에서:

   ```sh
   xattr -dr com.apple.quarantine /Applications/Storager.app
   ```

### 전체 디스크 접근 권한

첫 실행 때 권한이 없으면 안내 창이 한 번 뜹니다. 스캔은 막지 않으므로 "권한 없이 계속" 을 눌러도 됩니다. 나중에 팝오버 배너의 `권한 허용…` 으로 다시 열 수 있습니다.

권한이 없으면 macOS 가 보호 폴더마다 동의 창을 띄우기 때문에, 스캔은 아래 위치를 읽지 않고 건너뜁니다. 건너뛴 곳은 크기에 포함되지 않고, 팝오버에 "권한이 없어 N곳을 건너뜀" 배너로 알려 줍니다.

- 데스크탑, 문서, 다운로드, iCloud Drive
- 다른 앱의 데이터(컨테이너), 클라우드 저장소, 연락처, 캘린더
- 사진 보관함(`*.photoslibrary`)
- 메일·Safari·메시지 같은 폴더도 권한이 있어야 크기를 셀 수 있습니다

정확한 합계를 보려면 권한을 허용하는 것을 권장합니다.

1. 안내 창 또는 설정 창에서 "시스템 설정 열기"
2. 시스템 설정 → 개인정보 보호 및 보안 → 전체 디스크 접근 권한 에서 Storager 를 켭니다. 목록에 없으면 `+` 버튼으로 `/Applications/Storager.app` 을 추가하세요.
3. 안내 창의 "다시 시작" 을 누릅니다.

권한이 허용된 것을 감지하면 바로 다시 스캔합니다. 설정 창의 "전체 디스크 접근" 항목에서 현재 상태("허용됨" / "허용 안 됨")를 볼 수 있습니다.

### 업데이트

0.1.0 에는 자동 업데이트(Sparkle)가 없습니다. 새 버전은 Releases 에서 zip 을 다시 내려받아 `/Applications/Storager.app` 을 바꿔 주세요 (Storager 를 종료한 뒤 교체). 같은 인증서로 서명된 빌드라면 전체 디스크 접근 권한은 유지됩니다.

## 사용법

Dock 아이콘 없이 메뉴바에만 있습니다. 기본 표시는 디스크 아이콘 옆에 남은 용량(예: `812G`)이고, 스캔 중에는 아이콘이 은은하게 깜빡입니다. 앱 시작 30초 뒤 첫 스캔을 하고, 그 뒤로는 설정한 주기마다 다시 스캔합니다. Storager 는 한 번에 하나만 실행됩니다.

### 팝오버

메뉴바 아이콘을 누르면 열립니다.

- 위: 볼륨 막대(사용 / 퍼지 가능 / 여유)와 "사용 가능" 용량(Finder 의 "사용 가능" 과 같은 값), 마지막 스캔 시각
- 가운데: 카테고리 카드. 크기와 7일 변화량, 도구가 둘 이상인 카테고리는 도구별 크기 한 줄(예: "pnpm 12 GB · npm 3.1 GB")을 보여 줍니다. 카드를 누르면 분석 윈도우가 그 카테고리로 열립니다. 정리할 수 있는 카테고리에는 "정리" 버튼이, 명령으로 정리해야 하는 카테고리에는 "v0.2 에서 지원" 이 보입니다.
- 아래: 지금 스캔, 분석 윈도우 열기, 설정, 종료

### 분석 윈도우

왼쪽 사이드바로 네 가지 보기를 오갑니다.

- **홈 트리맵**: 큰 덩어리를 면적으로 보여 줍니다. 칸을 누르면 들어가고 브레드크럼으로 돌아옵니다. 칸 색은 경로에서 뽑은 고정 색이라 재스캔·재시작해도 같은 폴더는 같은 색입니다. 분류된 칸은 위쪽 카테고리 색 띠와 기호 배지로 구분합니다. 우클릭: Finder 에서 보기, 경로 복사, 정리, 무시 목록에 추가(다음 스캔부터).
- **카테고리**: 카테고리별 항목 표(경로, 크기, 마지막 수정, 등급, 도구). 도구가 둘 이상인 카테고리는 사이드바에서 펼쳐 도구별로 거를 수 있습니다. 여러 항목을 골라 "선택 항목 정리" 할 수 있습니다.
- **큰 파일**: 크기 순 상위 200개 파일 (설정의 "큰 파일 기준" 이상인 파일)
- **트리**: Finder 목록 보기처럼 펼치는 폴더 계층. 크기, 부모 대비 비율, 하위 파일 수, 카테고리, 도구 열이 있고, 이름 옆 색 견본이 트리맵 칸 색과 같습니다. 우클릭 메뉴에 "트리맵에서 보기" 가 있습니다.

### 정리

분류된 항목에는 안전 등급이 붙습니다.

| 등급 | 뜻 | v0.1 에서 |
|---|---|---|
| 재생성 가능 | 지워도 다음 빌드·실행 때 다시 만들어지는 것 (DerivedData, `node_modules`, `~/.gradle/caches` 등) | 정리 가능 (휴지통 이동 항목만) |
| 주의 | 다시 받는 데 오래 걸리거나 사용자 데이터가 섞일 수 있는 것 (Xcode Archives, AI 도구, Docker 등) | 정리 버튼 없음 |
| 수동 확인 | 메일·메시지·사진 등 | Finder 에서 보기·경로 복사만 |

v0.1 은 **"재생성 가능" 등급이면서 정리 방법이 휴지통 이동인 항목만** 정리할 수 있습니다.

1. 팝오버 카드의 "정리", 카테고리 보기의 "선택 항목 정리", 트리맵·트리의 우클릭 "정리…" 로 시작합니다.
2. 미리보기에서 대상 경로, 크기, 등급, 예상 회수 용량, 경고를 확인합니다. 관련 앱(Xcode, Simulator, Docker, Android Studio)이 실행 중이면 경고가 붙습니다.
3. "휴지통으로 이동" 을 누르면 실행 직전에 스캔 결과와 권한 상태를 다시 확인합니다. 그 사이 바뀌었으면 실행하지 않고 "다시 계획" 을 요구합니다.
4. 항목은 휴지통으로 옮겨지므로 되돌릴 수 있습니다. **휴지통을 비워야 디스크 공간이 실제로 늘어납니다.**

`brew cleanup`, `npm cache clean`, 시뮬레이터 정리(`xcrun simctl`)처럼 도구 명령이 필요한 정리와 "주의" 등급 정리는 v0.2 에서 지원할 예정입니다.

### 설정

메뉴바 아이콘 → 팝오버의 `설정` 에서 엽니다.

**일반**

- 로그인 시 실행: 기본값은 꺼짐입니다. 주기 스캔은 앱이 실행 중일 때만 돌므로 켜 두기를 권장합니다. macOS 가 승인을 요구하면 시스템 설정 → 일반 → 로그인 항목에서 Storager 를 허용해 주세요.
- 메뉴바 표시: 프리셋(남은 용량 / 사용률 / 남은 비율 / 사용 중 용량 / 아이콘만) 또는 직접 입력한 템플릿
- 전체 디스크 접근: 현재 상태와 시스템 설정 열기 버튼

**메뉴바 템플릿**

| 토큰 | 뜻 |
|---|---|
| `{icon}` | 디스크 아이콘 |
| `{remain_storage}` | 남은 용량 (Finder 의 "사용 가능") |
| `{remain_percent}` | 남은 비율 |
| `{using_storage}` | 사용 중 용량 |
| `{using_storage_percent}` | 사용률 |
| `{total_storage}` | 전체 용량 |

- 예: `{icon}{remain_storage}` (기본값), `{icon}{using_storage_percent}`, `{icon}하하하{using_storage_percent}`
- 토큰이 아닌 글자는 그대로 보입니다. 모르는 토큰(`{foo}`)도 글자 그대로 보이고 설정 창에 경고가 뜹니다.
- 템플릿을 비우는 등 보이는 것이 없으면 아이콘만 표시합니다. 최대 100자입니다.
- 템플릿 입력란 오른쪽 `?` 를 누르면 토큰 목록과 지금 볼륨 값으로 만든 예시가 보입니다. 아래 미리보기에 메뉴바 모양이 바로 보입니다.
- 크기: 100~200% (10% 단위). 메뉴바보다 커지면 줄이지 않고 위아래가 잘립니다.
- 템플릿 이미지로 표시: 기본 켜짐. 메뉴바 색에 맞춰 단색으로 그립니다. 이모지를 원래 색으로 보려면 끄세요.

**스캔**

- 주기: 1 / 3 / 6 / 12 / 24시간 (기본 6시간). 배터리 전원이거나 저전력 모드이면 그 회차는 건너뜁니다. 팝오버의 "지금 스캔" 은 언제든 됩니다.
- 큰 파일 기준: 1 / 10 / 50 / 100 MB 이상 (기본 10 MB). 이보다 작은 파일은 폴더 합계에만 들어가고 큰 파일 목록·트리맵 칸에는 따로 보이지 않습니다.
- 제외 경로: 스캔에서 뺄 폴더. 홈 폴더나 추가 루트 자체는 제외할 수 없습니다.
- 무시 목록: 트리맵·트리 우클릭 "무시 목록에 추가" 로 넣은 폴더. 목록에서 지우면 다음 스캔부터 다시 셉니다.
- 추가 프로젝트 루트: 홈 밖에 있는 레포(예: 외장 볼륨)를 스캔·분류 대상에 넣습니다. 홈이나 다른 추가 루트와 겹치는 폴더는 받지 않습니다. 추가 루트 안의 항목도 정리할 수 있습니다.

주기 외의 스캔 설정은 다음 스캔부터 적용됩니다.

## 데이터 위치

- 스냅샷 DB(`storager.sqlite`)와 단일 실행 잠금 파일: `~/Library/Application Support/Storager/`
  - 개발 빌드(`make run`)는 `~/Library/Application Support/Storager.dev/` 를 씁니다.
- 설정: UserDefaults 도메인 `com.wjbyun.Storager` (개발 빌드는 `com.wjbyun.Storager.dev`)
- 스냅샷은 90일이 지나면 하루 1개로 줄이고, 1년이 지나면 지웁니다.
- 스캔 결과와 스냅샷은 이 Mac 안에만 저장되며, 어디로도 보내지 않습니다.

완전히 지우려면:

1. 설정에서 "로그인 시 실행" 을 끄고 Storager 를 종료합니다.
2. `/Applications/Storager.app` 을 지웁니다.
3. 데이터와 설정을 지웁니다.

   ```sh
   rm -rf ~/Library/Application\ Support/Storager
   defaults delete com.wjbyun.Storager
   ```

4. 필요하면 시스템 설정 → 개인정보 보호 및 보안 → 전체 디스크 접근 권한 에서 Storager 를 `-` 로 뺍니다.

## 소스에서 빌드 (개발자용)

Xcode 16+ (또는 Swift 6 툴체인) 필요. 의존성은 GRDB 하나이며 첫 빌드 때 내려받습니다.

```sh
git clone https://github.com/WoojinByun/Storager.git
cd Storager

make cert                  # 최초 1회: 자체 서명 인증서 "Storager Local Signing" 생성 (로그인 암호 입력)
make install               # release 빌드 → /Applications/Storager.app 으로 복사 후 실행
make run                   # debug 빌드를 build/debug/Storager.app 으로 서명해 실행 (개발용)
make test                  # swift test
make app VERSION=x.y.z     # build/Storager.app (release) 빌드 + 서명. VERSION 기본값 0.1.0
make icon                  # Resources/AppIcon.svg -> Resources/AppIcon.icns (아이콘을 바꿨을 때)
```

`make run` 의 개발 빌드는 번들 ID 가 `com.wjbyun.Storager.dev`("Storager Dev")라 설치본과 동시에 띄울 수 있고, 설정·로그인 항목·데이터 폴더가 설치본과 섞이지 않습니다.

`make cert` 가 필요한 이유: ad-hoc 서명은 재빌드마다 서명이 달라져 전체 디스크 접근 권한이 초기화됩니다. 고정된 자체 서명 인증서로 서명하면 재빌드해도 권한이 유지됩니다. 마지막 단계에서 인증서를 코드서명용으로 신뢰하려고 macOS 가 로그인 암호를 묻습니다. 인증서 없이 빌드만 확인하려면 `SIGN_IDENTITY=- make app` 으로 ad-hoc 서명할 수 있습니다 (배포용이 아님).

- `StoragerCore`: UI 의존 없는 라이브러리. 스캐너(`getattrlistbulk`), 트리 모델, 분류 규칙, 정리 플래너·실행기, 스냅샷 저장소(GRDB), 트리맵 레이아웃, 설정
- `Storager`: 실행 타깃 (AppKit + SwiftUI). 메뉴바·팝오버, 분석 윈도우, 설정 창, 스케줄러
- `StoragerCoreTests`: Swift Testing 단위 테스트

## 알려진 제약

- 휴지통으로 옮긴 항목은 휴지통을 비우기 전까지 디스크 공간을 차지합니다.
- 도구 명령이 필요한 정리(Homebrew, 시뮬레이터, Docker, npm 캐시 등)와 "주의" 등급 정리는 아직 안 됩니다 (v0.2).
- 홈 밖은 추가 프로젝트 루트만 스캔합니다. 시스템 영역(`/Library`, `/private/var` 등)은 분석하지 않습니다.
- APFS 클론 파일은 중복 제거하지 않고 각각 셉니다 (`du` 와 같은 방식). 하드링크는 한 번만 셉니다.
- 늘 배터리 전원이나 저전력 모드로 쓰면 자동 스캔이 일어나지 않습니다 ("지금 스캔" 만 가능).
- 무시 목록 추가는 다음 스캔부터 반영됩니다.
- 전체 디스크 접근 권한을 허용한 직후에는 같은 범위의 기준 스냅샷이 없어 7일 변화량이 잠시 보이지 않을 수 있습니다.
- `~/Library/Caches` 중 접두사 없는 일부 Apple 캐시(`GeoServices` 등)는 일반 캐시(재생성 가능)로 분류됩니다.
- 추가 프로젝트 루트가 외장·네트워크 볼륨에 있으면 첫 스캔에서 macOS 의 볼륨 접근 동의 창이 뜰 수 있습니다.
- 트리맵 칸 글자는 중간 회색 바탕에서 읽기 어려울 수 있고, 칸 색은 다크 모드에 맞춰 바뀌지 않습니다.
